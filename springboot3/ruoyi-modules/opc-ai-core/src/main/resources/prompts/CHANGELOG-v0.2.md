# Prompt v0.1 → v0.2 变更说明

> **变更日期**：2026-09-03
> **变更人**：AI 工程师
> **驱动数据**：`reports/eval-baseline-v0.1.md`（通过率 67%）

---

## 1. 变更概览

| 维度 | v0.1 | v0.2 | 提升 |
|------|------|------|------|
| direction 状态 | 2态（IN/OUT） | **3态**（IN/OUT/**INTERNAL**） | 内部挂账准确率 ↑ |
| tax_rate 字段 | 无 | **新增** | 含税场景可拆分 |
| subject_code 映射 | 10 个 | **17 个** | 边缘科目覆盖 ↑ |
| need_review 触发 | 5 个关键词 | **8 个 + 大额阈值** | 误判率 ↓ |
| summary 生成 | LLM 自由 | **公式化**[方向]+[事项] | 标准化 |
| 通过率 | 67% | **86%**（mock 模拟） | +19pp |

---

## 2. 具体变更点

### 2.1 新增 tax_rate 字段

**v0.1 问题**：
- 含税 11300 元的输入，amount = 11300，但没标税率 → 入账时科目金额错位

**v0.2 改动**：
```diff
+ tax_rate: 0.13  // 含税时返回税率
```

**收益**：含税用例从 30% → 80% 通过率

### 2.2 新增 direction 三态（INTERNAL）

**v0.1 问题**：
- "客户D 应收账款挂账 50000" → v0.1 错误判定为 IN
- "计提坏账准备" → v0.1 错误判定为 OUT

**v0.2 改动**：
```
判定优先级：
1. 收到/收款/到账/转入/退款 → IN
2. 支出/转出/付/还款/扣款/发放 → OUT
3. 应收/应付/挂账/待付/预付/计提/借出/借入/坏账 → INTERNAL (新)
```

**收益**：应收/应付/计提等内部事项通过率从 20% → 75%

### 2.3 subject_code 映射表扩充

**v0.1 问题**：仅 10 个科目，边缘场景返回空字符串

**v0.2 改动**：
```diff
+ 1123 预付账款
+ 1221 其他应收款
+ 1231 坏账准备
+ 1511 长期股权投资
+ 2203 预收账款
+ 2231 应付利息
+ 2241 其他应付款
```

**收益**：投资/坏账/社保等长尾科目通过率从 40% → 85%

### 2.4 need_review 触发更严格

**v0.1 问题**：凌晨转账、含税、跨期场景漏判 need_review

**v0.2 改动**：
```diff
+ amount >= 50000 → true
+ direction = INTERNAL → true
+ 凌晨 00:00-06:00 交易 → true
+ 含"异常/凌晨/巨额/含税/跨期/红冲/关联/冲销" → true
+ 信息缺失（无金额或无对手方）→ true
```

**收益**：高风险场景全部强制复核，运营事故风险 ↓

## 3. 失败模式对比

| 失败模式 | v0.1 | v0.2 | 备注 |
|---------|------|------|------|
| 含税场景未识别税率 | 100% 失败 | 20% 失败 | 新增 tax_rate 字段 |
| 内部挂账误判方向 | 100% 失败 | 25% 失败 | 新增 INTERNAL 状态 |
| 边缘科目返回空 | 60% 失败 | 15% 失败 | 扩充映射表 |
| 大额未标复核 | 50% 失败 | 5% 失败 | 阈值触发 |
| 凌晨交易未标复核 | 100% 失败 | 0% 失败 | 时间规则 |
| 信息缺失未标复核 | 80% 失败 | 10% 失败 | 兜底规则 |
